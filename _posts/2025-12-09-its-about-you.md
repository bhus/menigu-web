As LLMs continue to progress at an astounding rate, I think something is becoming clear for those of us that deal in code daily. It's not about the AI, it's about us.

#### All Engines Go!

The last year or 2 has seen an exponential improvement in developer productivity, but *not* an improvement in the UX for software developers. We now have a tool that writes code, and automates away a lot of tediousness, which has always been the dream of the computer scientist. We appreciate complexity, and even enjoy working in it. But unncessary, gate-kept tech secrets are something we are happy to get rid of. Complexity should not be in our tools -- it should make tools easier to use so we can focus on the complexity of the problems we are actually trying to solve.

## A Worthy Apprentice

And so LLMs have performed admirably, deftly handling complexity and bringing the *intent* of the software developer front and centre. It has performed admirably, each generation of progress bringing more delight.

## The student becomes the master becomes the student

But as we work with LLMs to product code & products, it becomes crucially important that *we* are able to in turn grok the work the LLM has done. LLMs can be excellent teachers, but obviously cannot transform the underlying material. So the frameworks in which we build constrain us. Or at least, they *can*.

## Keep evolving

We must make it a goal to *keep evolving*, together. Not just in the work we do, but in the platforms we target. The frameworks themselves must evolve with these new patterns of use, in no small part so that we can continue to understand the work being done more easily.

[ And added perk to this is that it is now easier than ever to switch frameworks, since this task itself can be automated with the use of LLMs ]
